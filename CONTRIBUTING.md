# Cómo aportar una nota

Escribe para alguien que aún no conoce la respuesta. Explica primero el problema, después el concepto y finalmente cómo comprobarlo. Define las siglas al introducirlas.

- Usa `docs/` para explicaciones, `laboratorios/` para ejercicios y `bitacora/` para experiencias ejecutadas. Numera las lecturas para conservar su orden.
- Enlaza desde el README cualquier capítulo nuevo y desde el capítulo su práctica.
- Distingue **documentado**, **hipótesis**, **resultado esperado** y **observado**. Nunca presentes una salida inventada como ejecución real.
- Cita documentación oficial y especifica la versión cuando el comportamiento dependa de ella. Una experiencia aislada no demuestra una regla universal.
- Incluye requisitos, comandos, resultado esperado, comprobación y limpieza. Explica cualquier operación destructiva antes del comando.
- Usa solo datos ficticios. No publiques expedientes, nombres reales, contraseñas, cadenas de conexión completas ni archivos de respaldo.
- No añadas dependencias para documentación. Si aparecen pruebas automatizadas, colócalas en una subcarpeta `tests/` de la parte a la que pertenecen.

Antes de proponer cambios, revisa los enlaces locales y ejecuta las prácticas si tienes el entorno. Si no puedes ejecutarlas, decláralo; documentar una limitación es mejor que fabricar evidencia.
